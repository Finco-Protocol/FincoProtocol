# F03 — distinguishing committed Runs: contract, fix, acceptance

## Reproduced

Two Runs committed within seconds of each other on one project (Solar probe, real engine; evidence screenshot `screenshots/after-run-history-two-runs.png` shows them as `2026-10-27 01:42:16 UTC · 207393` and `2026-10-27 01:42:14 UTC · 704771`):

* canonical snapshot ids have the shape `YYYYMMDDTHHMMSS.ffffff+0000` (UTC commit instant, separators removed, microseconds; see
  `app/services/run_service._utc_now_iso_compact`). Two Runs committed seconds apart, e.g. at 01:42:14 and 01:42:16, therefore start
  with the same 12 characters `20261027T014`;
* every React surface printed `snapshot_id[:12]` = `20261027T014` — the same text for **every** Run committed within the same
  ten minutes. Results, Overview, Scenarios, Export and the Library all showed that truncated text; the Run History table showed
  the full id but only as a secondary line.

(`snapshot_id[:12]` is not a database key anywhere; it was purely a display truncation. Persisted history ids and snapshot
ids are unchanged.)

## One presentation contract

`frontend/src/app/runIdentity.tsx` (single module, used everywhere a Run is named):

* Human label: `2026-10-27 01:42:16 UTC` — the commit instant to the second, read from the canonical snapshot id.
* Stable suffix: `· 207393` — the canonical sub-second digits of that same id. Two Runs in the same second still differ.
* Full identifier on demand: an `ID` disclosure (native `<details>`, keyboard operable) shows the full snapshot id and, when the
  surface has it, the Run History id, each with a `Copy` button whose accessible name says what it copies; the ids are also
  selectable text.
* Data attributes: `data-run-identity="<full snapshot id>"` and `data-run-history-id="<history id>"` bind each displayed Run to its
  exact canonical identifiers (used by the tests).
* A snapshot id that is not in the canonical shape (legacy or mocked) is shown **verbatim and never shortened**; an empty one is
  "No persisted Run". Nothing is generated or guessed. A Python mirror (`tests/react_run_identity.py`) is proven equal to the
  real TypeScript function by `test_the_python_mirror_equals_the_real_typescript_run_identity_module`.

Applied to: Results (Run context), Overview (Last Run), Statements header and trace text, Scenarios (per-scenario committed Run
evidence, assumption compare, Run-picker labels), Run History (now one row per Run led by the identity), Export (Last committed Run
and Historical Runs), Diagnostics/Trust identity lines, and the Project Library. The Financial-insights pages already printed
full ids and keep them.

Backend (presentation only, `react_workspace_router.py`): `statements.status.runId` and `library.*.last_run.snapshot_id` now carry the
full snapshot id instead of its first 12 characters. No history id, snapshot id, binding or CAS value changed.

## Limits

* The suffix is the sub-second part of the canonical snapshot id. If a future snapshot-id format drops sub-second digits the
  label falls back to the second-precision time only; ids in the old shape without a fraction are handled.
* Export **files** (XLSX) are generated by backend services outside this PR's scope; only the UI's Run naming changed.
