Likewise a record built from whatever XML exists does not prove the complete inventory executed. The design must address provenance, repeated source evaluation, scheduling and completeness together.

This Draft has not proven the successor and therefore keeps the candidate inert. No independent reviewer has approved this Draft. Current settings were not altered.

A sealed bundle names exact source, run, attempt, runtime/archive digests, full inventory, policy, groups and weights. Ownership is re-derived, not trusted from a worker. Every worker must reproduce full collection; selected nodes must equal its disjoint ownership, while deselected nodes equal exactly all other owners. Every phase and native case is checked. Missing/duplicate nodes, phase/native disagreement, cleanup/timeout/source/plugin drift and new unauthorized nonpass fail closed.

Historical baseline must be independently authenticated by the controller; this candidate does not require a green accepted-source FULL of itself. All original outcomes remain exact except the existing single D-029 transition, through the unchanged existing verifier supplied by trusted controller code and all same-run evidence. A worker may never supply that callback or source facts. The pure verifier is not an authentication service.

The service-data function checks run/repository/event/source/attempt, exact artifact identity set, successful producer jobs and ZIP digest bytes. Safe extraction, comparing extracted files to verifier inputs, runtime archive verification and immutable baseline authentication remain controller responsibilities and ARE NOT wired up here. It returns no FULL_PROVEN_GREEN verdict. Runtime calibration re-evaluates raw samples against the existing approved contract.

The scoped_evaluate experiment enters and exits one fresh outer call. It is not installed as a plugin, autouse fixture, session cache or historical module replacement. benchmark_scope exercises real source mutation, restoration and ref separation on a disposable clean clone.
