## 2. What F3.7 adds
- `app/v2/financing_instrument_reconciliation.py` (new): verification-only. Reads the exact Run's facility ledgers and the already validated aggregate lines; returns per-instrument commitment (contractual) vs actual construction draws, IDC, upfront and commitment fees, funding state, per-period rows, an equity / SHL construction ledger split, and a reconciliation table. It imports no engine, core, persistence or writer.
- `financing_sources_uses_projection.py`: one additive key, `instrument_view`.
- Template section "Funding by instrument" (expandable per-instrument period evidence, equity split, reconciliation table, Capital Stack link, explicit UNAVAILABLE for aggregate-only Runs); `model_financing_sources_uses.css` additions plus a mobile overflow fix for long authority paths in the totals cards.

## 3. Rules enforced
- A commitment is never shown as drawn; "PARTLY DRAWN" is stated from the persisted draw ledger.
- Every cost has one home: Senior IDC -> Capitalised IDC; Junior IDC -> Other financing costs; upfront fees -> structuring; Σ instrument ledgers must equal each aggregate line or the row shows DIFFERS with the difference (never plugged, never repaired).
- Malformed evidence (non-finite, wrong length, overdrawn, duplicate or missing ids, incomplete Junior block) is rejected (HTTP 409 path); Run binding checks are the existing F1 ones.
- No Balance S&U action; Junior activation stays closed (`ACTIVATION_ENABLED=False` on this branch; the Junior fixture sets it only inside a test).

## 4. Still unavailable, and why
- Instrument split for single-Senior sizing Runs and legacy Runs: the Run persisted no instrument ledgers. Deriving them from commitments would present a commitment as funding drawn.
- Operating-period (post-COD) funding is out of scope: S&U is a construction-period statement.
- If VAT IDC/fees ever make an instrument ledger differ from an aggregate line, the page reports DIFFERS; extending the canonical serializer would be a separate financial-authority amendment (not made here).
