## Implemented: O8 - diagnostic-only metric computed only where it is reported

`_compute_max_abs_diff` fed only `SolverDiagnostics.maximum_absolute_difference_keur`. Acceptance is decided by `_schedules_converged`,
which is unchanged and still evaluated every iteration. In `_solve_dscr` and `_solve_gearing_sculpted` each iteration overwrote the previous
value, and the value was read only by the diagnostics of the iteration that returns: a converged iteration (CONVERGED,
FINALISATION_NOT_CONVERGED, DSCR_SCULPTING_INFEASIBLE) or the last allowed iteration (MAX_ITERATIONS_REACHED reports the last computed value).
The metric is now computed on exactly those iterations (`converged or iteration == max_iter`), from the same arguments, so the reported
float is identical. The iteration path, tax callbacks, rolls and finalisations are untouched. `_solve_gearing` (single pass) and
`_solve_combined` do not compute the metric themselves.

Equivalence argument: (1) `_compute_max_abs_diff` is a pure function of its arguments and raises nothing for numeric rows; (2) its result
is never read by a branch, only stored; (3) every observable read happens on a returning iteration, where it is still computed with the
same inputs; (4) iteration 1 of the DSCR loop never computed it (`prev_rows is None`) and still does not (max_iter == 1 keeps `inf`).

## O1 - finalisation reuse: proven NOT bit-identical, not implemented

When DSCR binds, COMBINED_MINIMUM sizes the same debt as the DSCR loop but then re-runs `_finalise_authoritative` starting from zero CFADS.
The DSCR loop's own finalisation starts from the converged CFADS. Both end inside tolerance but at different fixed points: on 60 synthetic
DSCR-binding cases with tax feedback the debt is identical and the interest vector differs in the last digits in 60 of 60 (up to
1.8e-6 kEUR). On the Solar and Wind reference Runs the combined final debt never equals the DSCR-solved debt (0 of 102 and 0 of 152
consecutive DSCR/combined finalisation pairs share a debt, i.e. the gearing cap is the lower bound), so reuse would not even apply there. Reusing the DSCR result would change output bits, so it is not done. The characterisation
test `test_o1_reuse_of_the_dscr_finalisation_is_not_bit_identical_so_it_is_not_implemented` records this. No warm-started finalisation and
no seed change (V8-B2, Finance approval).
