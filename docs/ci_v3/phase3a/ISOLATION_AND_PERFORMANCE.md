# FINCO source isolation and bounded measurement plan

Actual source findings, not certification from the synthetic suite:

| Concrete source | Risk and conservative mechanism |
|---|---|
| `tests/conftest.py` module-autouse executor lifecycle and session-finish hook | The global executor is reset/joined after each module; shutdown failures remain failures. Whole-module ownership preserves that fixture boundary. Shared/order-sensitive module families require reviewed colocation. |
| `tests/model_decision_workspace_browser.py`, financing/browser helpers | Mutate `app.persistence.db.DB_PATH`, use SQLite and bind ephemeral loopback ports. Each job/container receives private source/database/temp and network namespaces; restoration/import interactions still need explicit helper/order review. |
| `tests/test_p0a_model_execution.py` | Real process/thread pools and local HTTP requests. Preserve all cleanup assertions, restrict lifetime/PIDs and validate descendants. Loopback is available inside the private namespace; no external egress is granted. |
| `tests/model_v2_governance.py` | Full `origin/main` ancestry is required in CI. Preserve complete public Git objects/refs in the private checkout; do not turn missing ancestry into a skip. |
| `tests/rc7b_quarterly_candidate_authority.py`, Gate-R authorization tests | GitHub HTTP helper and mocked responses need source review to distinguish intentional mocks from external resource requirements. Genuine external-network requirements are unsupported and block this profile. |
| Authentication/tenant and persistent-history tests | Private files/databases avoid cross-runner collisions; global app sessions/caches and imported fixtures can still couple module order. Require exact decisions/colocation or block. |
| Numerical/financial and quarterly tests | Pin image, dependencies and thread environment; never alter tolerances, golden results, financial code or negative controls. A parallel PASS is not financial acceptance. |

`ci_v3_isolation.assess` inventories every Python file under tests, recording exact bytes, line evidence for databases/files/network/auth/thread/environment/global-state/session fixtures, and blocked defaults. String matches are risk leads, not assertions that every match executes a dangerous operation. Nested/dynamic fixture construction and imported application behavior require manual review. Session-scoped synthetic fixtures test the mechanism; absence of an obvious top-level session fixture in one scan does not prove absence of session coupling. Current collection and full static inventory are delivered as external evidence so they bind the final committed source rather than a stale historical count.

The historical large F set is never assigned away or selectively omitted. Current preparation conservatively marks every collected node mandatory/unresolved F until independent source classification/review; original full node identities and collection skip records are retained. Static decisions do not automatically approve any real FINCO module. Unresolved module/shared-resource scope remains blocked. Exact blob changes invalidate previous reviews. This is an explicit implementation restriction, not a declaration that FINCO is already safely parallelizable.

## Performance plan

Use the final current collect-only inventory, not 15,440 as a constant. The delivered proposal includes a deterministic three-way node-count distribution as a planning proxy; proxy integer weights are not measured milliseconds. For a time projection, independently bind prior measured module durations only where source/environment equivalence is justified, measure new modules and account for co-location. Report each worker's complete module/node set, estimated sum and the largest sequential group. Do not add a fourth worker.

Historical comparison remains a prediction: slow-cohort three-worker estimate 32.78 minutes (34–45 minute planning range), 99.71 worker-minutes and 95.98 sequential minutes, approximately 195.69 pytest runner-minutes for a pair. The faster cohort predicted 19.99 minutes. These numbers do not measure this changed current suite, its new quarterly tests or container startup/transport. Rough 90–100 minute sequential and 35–45 minute shadow objectives must be re-measured; unknown isolation bottlenecks can exceed the target.

Record actual local startup/import/collection/phase/JUnit-copy/aggregation/shutdown overhead from the real small demonstrations separately. Hosted image pull, source/history copy, container startup, full collection, archive upload/download and verification overhead remain unmeasured before authorization. Capture per-stage monotonic telemetry, original process logs and service job timestamps in the future experiment; no throughput or runner-minute result may be inferred from tiny tests.

Initial experiment: one independently authorized control/shadow pair on one immutable source tree. No automatic repeats/retries or three-pair schedule. Keep existing mandatory sequential acceptance unchanged. Establish comparable Python/dependency/native-thread settings and platform for both sides before interpreting speedup. The shadow image fixes native thread variables to one; a control with different settings is not an equivalent performance reference. Owners must resolve that comparison prerequisite separately without silently editing the protected mandatory workflow. If comparable control evidence is unavailable, report the performance comparison as inconclusive.

Candidate allocations: admission 10 minutes, trusted planning/image preparation 25, three worker jobs 100 each (4800-second observed execution budget), aggregation 15: 350 shadow runner-minutes allocated. Existing control 220 plus ten-minute source and ten-minute mandatory aggregation allocations give 590 enumerated runner-minutes for the pair, excluding other existing policy workflows and queueing. This is a hard allocation ceiling, not expected usage. Expected pytest consumption starts near the historical 196–221 minute planning range, with current-suite, container, isolation and transfer costs additional/unknown. Shadow critical allocation is 150 minutes; retain a proposed 250-minute full-comparison wall budget excluding queues, subject to owners reconciling actual control settings.

Stop on source/merge/manifest/environment drift, unresolved isolation, unknown/missing nodes, unexpected skips, incomplete/foreign evidence, failed/abnormal/timed-out processes, cancellation or budget exhaustion. Admission/discovery failure starts no workers; a worker failure leaves siblings collecting evidence. Terminate only owned containers/process groups. Upload failure evidence where possible with 14-day retention; absent artifacts fail. End after the one pair and seek a new decision for any additional attempt.
