Introduction

Model scope and design principles.

The FINCO financial engine is a deterministic, pure-Python project-finance model for infrastructure and renewable-energy assets. It covers four calculation phases:

  1. Phase 2A — Operating model: Revenue, OPEX, EBITDA, depreciation.
  2. Phase 2B — Tax + CFADS: Phase 2A plus annual corporate tax and canonical CFADS.
  3. Phase 2C — Senior debt: Phase 2B plus DSCR-sculpted debt sizing.
  4. Returns: Project IRR (unlevered), Equity IRR, Sponsor XIRR, MOIC.

Each phase builds strictly on the one before it. Financial economics are never changed to make methodology easier to explain; this document traces every formula to the production authority.

Temporal framework

Period convention: SEMESTRIAL.

The engine divides time into semiannual (6-month) periods. Each operating year is represented by exactly two periods (H1 and H2). Construction years may use the same grid.

# finco_core/engine/period_engine.py PeriodFrequency.SEMESTRIAL # = 2 periods per year # Day fraction for each period: day_fraction = days_in_period / 365 # or /366 in leap year end # Operating period count: operating_period_count = horizon_years × 2 # (2 per year)
finco_core/engine/period_engine.py

Period indexing

Under the default COD_ANCHOR_TWO_CONSTRUCTION_COLUMNS convention, indices 0 and 1 are construction columns; operating periods start at index 2. Each period carries: start_date, end_date, year_index (1-based operating year), period_in_year (1 = H1, 2 = H2), and day_fraction.

COD stub roll: if COD falls within 7 days before a semiannual boundary, the first operating period snaps to that boundary.

Capital expenditure

CAPEX structure.

CAPEX is the sum of all hard and soft development costs incurred during the construction phase. The engine uses a bottom-up taxonomy of named line items, each with an asset class and (optionally) a spending profile across construction periods.

# finco_core/inputs/_models.py total_capex_before_idc = ( hard_capex_keur + commitment_fees_keur + bank_fees_keur + other_financial_keur + vat_costs_keur + reserve_accounts_keur ) total_capex = total_capex_before_idc + idc_keur
finco_core/inputs/_models.py

Hard CAPEX line items include: Production Units (solar modules / wind turbines), EPC Contract, Grid Connection, Civil Works, Soft Costs, Owner's Engineering, Commissioning, Audit & Legal, Contingencies, Insurance, Lease & Tax, Project Acquisition, Project Rights.

Each line item carries a spending_profile tuple defining how costs are distributed across construction sub-periods. Interest During Construction (IDC) and bank fees are zeroed in the generic factory path; they are available as explicit inputs for project-specific models.

Revenue

Generation and revenue calculation.

Revenue is calculated bottom-up from physical generation, then split between PPA-contracted and merchant volumes.

# finco_core/revenue/generation.py # Physical generation per period: generation_mwh = ( capacity_mw × operating_hours_p50 × day_fraction × (plant_availability × grid_availability) × (1 − pv_degradation) ^ (year_index − 1) ) # Revenue split: ppa_mwh = generation_mwh × ppa_share merchant_mwh = generation_mwh − ppa_mwh energy_revenue_keur = ( ppa_mwh × ppa_tariff + merchant_mwh × market_price ) / 1000 # CO₂ revenue (if enabled): co2_revenue_keur = generation_mwh × co2_eur_mwh / 1000 # Balancing cost deduction: balancing_cost_keur = ( gross_merchant_revenue_keur × balancing_cost_pv + generation_mwh × balancing_eur_mwh / 1000 ) revenue_keur = energy_revenue_keur − balancing_cost_keur + co2_revenue_keur
finco_core/revenue/generation.py

For the Generic Solar Reference model, ppa_share = 1.0 for the first 10 PPA years (all generation contracted); thereafter the full volume switches to merchant pricing. PV degradation compounds annually.

Operating costs

OPEX projection.

Each OPEX line item has a Year 1 amount and an annual escalation rate. The schedule applies period-level day-fractions so that H1 and H2 periods receive their proportional share of annual cost.

# finco_core/opex/projections.py # Annual amount at year y: opex_year_v = y1_amount_keur × (1 + annual_inflation) ^ (year_index − 1) # Period amount: opex_period = opex_year_v × day_fraction
finco_core/opex/projections.py

Step changes are supported: when a step change is defined for a given year, the new level becomes the permanent base from that year forward (sustained, not one-off).

Earnings before interest, tax, depreciation & amortisation

EBITDA formula.

# finco_core/ebitda.py — single line, no adjustments ebitda_keur = revenue_keur − opex_keur
finco_core/ebitda.py

EBITDA at this layer carries no financing income, no depreciation add-back, and no non-cash adjustments. It is computed once per period by calculate_ebitda_keur() and re-used by every downstream calculation — tax, CFADS, DSCR, LLCR.

Corporate income tax

Tax calculation.

The engine computes corporate tax on an annual basis (calendar tax year), then distributes cash payment to the H2 period of the tax year. This produces the "clean cash tax timing" pattern used by the Solar and Wind reference models.

# finco_core/tax/engine.py # Taxable income per period: taxable_profit = ( EBITDA − tax_depreciation − deductible_interest # SHL + senior (subject to ATAD cap) + fiscal_reintegration − loss_carryforward_used ) # Tax liability: tax_liability = max(0, taxable_profit × corporate_rate) # ATAD interest limitation (EU anti-avoidance): atad_deductible_interest = max(ebitda × 0.30, 3_000.0) # kEUR floor # Loss carryforward: FIFO queue, max 5 years, 100% utilisation cap # Cash payment: H2 periods only (period_in_year == 2)

Cash flow available for debt service

CFADS formula.

# financial_engine/cfads.py line 91 — single authoritative location # Phase 2B definition: pre-debt-service, pre-DSRA cfads_keur = ebitda_keur + financing_income_keur − cash_tax_keur
financial_engine/cfads.py:91

calculate_canonical_cfads() is the single authoritative function. No other module in the codebase re-derives CFADS inline — all consumers call this function. For the Solar and Wind reference models, financing_income_keur = 0; the term is reserved for models that earn interest on cash reserve accounts.

CFADS is computed per semiannual period. The construction periods (indices 0 and 1) produce CFADS = 0.

Senior debt sizing

Backward induction + fixed-point iteration.

The senior debt size is determined by one of four sizing modes. For the Solar and Wind reference models, DSCR-sculpted (FLAT_DSCR_SCULPTED) is used; the binding constraint switches to GEARING_CAP when gearing capacity is the tighter limit.

Step 1 — DSCR backward induction

# financial_engine/senior_debt/solver.py:247–260 # Starting condition: closing_maturity = 0 # For t from maturity down to first repayment period: allowed_ds_t = max(0, cfads_t / dscr_target_t) × availability_t opening_t = (closing_t + allowed_ds_t) / (1 + rate_t × day_frac_t) # D = opening at first repayment period = DSCR capacity

Step 2 — Sizing mode selection

# financial_engine/senior_debt/solver.py:785 DSCR_SCULPTED: D = dscr_capacity GEARING_CAP: D = eligible_project_cost × maximum_gearing COMBINED_MINIMUM: D = min(dscr_capacity, gearing_capacity) # binding is lower EXPLICIT: D = schedule provided by caller

Step 3 — Fixed-point iteration

# financial_engine/senior_debt/solver.py # Convergence tested per field: converged = (|Δ| ≤ abs_tol) OR (|Δ| / max(|a|, |b|, 1) ≤ rel_tol) # Fields checked: debt_size, opening, interest, principal, # closing, CFADS, cash_tax # Finalisation sub-loop enforces exact interest/CFADS self-consistency.
financial_engine/senior_debt/solver.py

Forward roll — debt service schedule

# financial_engine/senior_debt/sculpting.py # Interest (rolling balance): interest_t = opening_balance × rate × day_fraction # DSCR-sculpted principal: max_ds_t = max(0, cfads_t / target_dscr) principal_t = max(0, min(max_ds_t − interest_t, balance_t)) # Level-principal alternative (for GEARING_CAP or EXPLICIT sizing modes): level_install = opening_debt / n_repayment_periods # Solar reference: FLAT_DSCR_SCULPTED amortization regardless of binding constraint.
financial_engine/senior_debt/sculpting.py

Coverage ratios

DSCR and LLCR.

# DSCR per period (finco_core/waterfall/waterfall_engine.py line 1022): dscr = ebitda_minus_tax / senior_debt_service # LLCR at period t (finco_core/waterfall/waterfall_engine.py lines 202–213): llcr_t = Σ[ fcf_s / (1 + rate)^(s−t+1) for s in remaining_debt_life ] / debt_balance_t
finco_core/waterfall/waterfall_engine.py

The lock-up DSCR gate is 1.10 for the Solar reference model: when dscr < 1.10 in any operating period, distributions to equity are blocked. LLCR is defined in the model architecture but is not configured in the Solar reference run (production output: min_llcr = None, status: C2_COVERAGE_CFADS_CASE_NOT_CONFIGURED).

Sizing vs amortization — important distinction. For the Solar Reference, the binding size constraint is GEARING: the loan amount is capped at 75% × 33,000 = 24,750 kEUR, because the DSCR capacity (36,113 kEUR) exceeds the gearing cap. Once the loan size is set by the gearing cap, the amortization schedule is still determined by DSCR-sculpted repayment (FLAT_DSCR_SCULPTED mode): each period's principal repayment is sized so that CFADS / debt service = target DSCR. Gearing constrains the size; DSCR sculpting determines the shape of repayment.

Debt service reserve account

DSRA mechanics.

# finco_core/waterfall/dsra_engine.py # Initial DSRA (funded at financial close by equity): initial_dsra = (dsra_months / 12) × first_period_payment × periods_per_year # Target DSRA in each period (rolling target): target_dsra = (dsra_months / 12) × current_period_payment × periods_per_year # Top-up from operating cash: top_up = min(available_fcf × 0.5, gap_to_target) # Release: DSRA balance released to distributions in final 2 operating periods.
finco_core/waterfall/dsra_engine.py

The Solar reference model has dsra_months = 6 in its configuration parameter, but the active production mode is dsra_support_mode = DebtServiceReserveSupportMode.NONE. This means: no reserve is funded at financial close, no reserve movements occur in any period, and debt_service_reserve_requirement_keur = 0. The terminal DSRA balance is 0 (status: NOT_APPLICABLE).

In short: the DSRA parameter exists and is configurable, but the Solar reference model intentionally runs without an active reserve. Full DSRA mechanics — initial funding by equity, rolling target top-up from operating cash, and release at maturity — are exercised when dsra_support_mode ≠ NONE in a project-specific model.

TRUST_PACK_SOLAR_DSRA_RUNTIME_RECONCILIATION: Solar Reference production output — dsra_support_mode = NONE, debt_service_reserve_requirement_keur = 0.0, terminal DSRA = 0. Configuration parameter dsra_months = 6 is stored but overridden by the active mode at runtime.

Shareholder loan

SHL schedule and waterfall priority.

# finco_core/waterfall/shl_engine.py gross_interest = shl_balance × shl_rate × day_fraction net_interest = gross_interest × (1 − wht_rate) cash_interest = min(net_interest, available_cash) pik_interest = gross_interest − cash_interest # PIK accretes at gross rate interest_wht = cash_interest × (wht_rate / (1 − wht_rate))
finco_core/waterfall/shl_engine.py

WHT is levied only on the cash-paid interest component, not on PIK accretion. Waterfall priority: SHL ranks junior to senior debt and ahead of equity distributions. The Solar reference model uses CASH_SWEEP repayment mode; SHL principal is swept from post-senior-debt cash after the senior loan reaches full maturity.

Repayment modes available: bullet, cash_sweep, pik, accrued, pik_then_sweep, partial_pay_sweep.

Project return

Project IRR — unlevered definition.

The Project IRR measures the return on the total project investment as if it were financed entirely with equity. It is explicitly unlevered: no senior debt service, no SHL interest, no financing benefits appear in the cash flows.

# financial_engine/project_returns/model.py lines 251–264 # Construction phases: outflows at the date of each CAPEX draw cf_construction[t] = −hard_capex_investment_t # Operating phases: EBITDA minus unlevered cash tax cf_operating[t] = ebitda_t − unlevered_cash_tax_t # Unlevered cash tax (from waterfall_engine.py line 1274): unlevered_cash_tax = tax_rate × max(0, ebitda − depreciation) # Net unlevered cash flow: net_ucf[t] = cf_operating[t] + terminal_component_t − cf_construction[t] # Project IRR = XIRR(net_ucf, dates)
financial_engine/project_returns/model.py
Excluded from Project IRR: explicit financing costs (IDC, bank fees, DSRA funding) are tracked separately in excluded_financing_cost_uses_keur and excluded_reserve_funding_keur and do not enter the unlevered cash flows. Soft costs and development fees that form part of CAPEX are included.

Equity and sponsor returns

Three distinct return metrics.

The engine produces three distinct return metrics. Each uses a different set of cash flows; comparing them directly is meaningful only when their definitions are understood.

1. Project IRR — unlevered

# financial_engine/project_returns/model.py # Authority: C1_UNLEVERED_HARD_CAPEX_PLUS_EBITDA_MINUS_ZERO_FINANCING_INTEREST_CASH_TAX construction_cf[t] = −hard_capex_draw_t operating_cf[t] = ebitda_t − unlevered_tax_t # no debt service project_irr = xirr(construction_cf + operating_cf, dates) # Solar reference: 11.56%

2. Equity IRR — legal equity only (EQUITY_ONLY)

# finco_core/waterfall/waterfall_engine.py # Solar reference equity_irr_method = 'equity_only' initial_outflow = share_capital_contributed_keur # 500 kEUR for Solar ref periodic_cf = equity_distributions_t # post-senior, post-SHL equity_irr = xirr(−initial_outflow + periodic_cf, dates) # Solar reference: 50.47% (leveraged; SHL excluded from this metric)

3. Total Sponsor XIRR — all sponsor cash (equity + SHL)

# financial_engine/sponsor_returns/model.py contributions = share_capital + shl_cash_contributed # 500 + 7,750 = 8,250 kEUR receipts = shl_cash_interest + shl_principal_repaid + equity_distributions total_sponsor_xirr = xirr(−contributions + receipts, dates) # Solar reference: 17.90% (diluted by SHL cost of carry)

Return calculation

XIRR date convention.

# finco_core/sponsor/xirr.py # 365-day year fraction (no leap-year adjustment): year_fractions = [(d − d₀).days / 365.0 for d in dates] # NPV at rate r: npv(r) = Σ[ cf_t / (1 + r)^year_frac_t ] # Newton–Raphson iteration, tolerance = 1×10⁻⁷, max 200 iterations # Fallback: bisection if Newton–Raphson diverges
finco_core/sponsor/xirr.py

XIRR is a pure-Python implementation — no external financial library. robust_xirr() tries Newton–Raphson first; on non-convergence, it falls back to bisection. Both paths are exercised in the regression suite.

Model governance

Working state vs Last Run.

The FINCO workspace maintains two distinct model states that must not be conflated:

  • Working state: the current parameter values in the workspace UI. These may have been edited since the last calculation. The working state is draft; it has not been validated by the engine.
  • Last Run: the frozen engine output produced by the most recent calculation. All published KPIs, schedules, and distributions are bound to Last Run. If the working state has been modified after the last run, the workspace is marked stale; if no run has been performed, it is NOT_RUN.

The Generic Solar Reference canonical model is always in a known Last Run state: its inputs are frozen, its outputs are deterministic, and the results on this page are bound to that Last Run. Any change to working state requires a new engine run before the outputs update.

TRUST_PACK_WORKING_LAST_RUN_CONTRACT: Export and report generation are bound exclusively to Last Run, not to working state. A stale or NOT_RUN workspace cannot produce a verified export.

Scope and limitations

What this model does and does not cover.

  • Asset classes covered today: Solar PV, Wind (onshore/offshore), Data Center, EV Charging Hub. Storage is in preview (reference workflow only).
  • Currency: All monetary values are in kEUR (thousands of Euros). Multi-currency models are not in scope for V1.
  • Period frequency: SEMESTRIAL only. Annual and quarterly modes exist in the codebase but are not exposed in the current UI.
  • Tax: A single corporate-income-tax jurisdiction is modelled. Transfer pricing, consolidated group tax, or country-specific thin-cap regimes beyond ATAD are not implemented.
  • Merchant price: The engine accepts a user-supplied merchant price curve or a default linear escalation from a base price. No stochastic price simulation is performed.
  • Inflation: Cost items escalate at user-supplied annual rates. The model does not produce real-terms versus nominal-terms comparison.
  • Refinancing: Not modelled. The senior debt schedule runs to its contractual maturity.
  • Distributions waterfall: The full covenant-gated waterfall (DSCR lock-up, DSRA top-up, SHL sweep, equity distribution) is implemented in finco_core/waterfall/waterfall_engine.py and is available for project-level models. The generic reference models use a simplified cash-sweep path.
  • LLCR: The Loan Life Coverage Ratio is defined in the model architecture but is not computed in the Solar Reference production path. Production output: min_llcr = None (status: C2_COVERAGE_CFADS_CASE_NOT_CONFIGURED).
  • Excel / XLSX export reconciliation: TRUST_PACK_SOLAR_EXCEL_RECONCILIATION = PASS. The Institutional XLSX Export (P1.2) is delivered. The workbook includes a Returns sheet (Project IRR, Equity IRR, Total Sponsor XIRR), a Run Identity sheet (run_id, project_id, engine version, export timestamp), and a Reconciliation sheet with explicit numeric checks: Sources = Uses, CAPEX detail = total, Revenue detail = runtime total, OPEX exported, Debt service period sum = runtime total, and all three return metrics exported = runtime values within tolerance.
