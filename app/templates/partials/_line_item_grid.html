The 57A migration preserves all of these class names on the rendered HTML so the existing CAPEX styling (in `static/styles.css`) continues to apply without modification. Why this approach ----------------- The first runtime grid migration is intentionally conservative: it preserves every CSS class on every element so the visual look is byte-for-byte identical to the old hand-written table. The benefit is the data model: the rows are now structured data, so the next migration (e.g. sheet_opex.html in UI-3.2) can reuse the same macro with a different rows list. Stable test marker ------------------ The wrapper always has class `lig-wrapper` and a per-table class `lig-capex-pilot` (currently hard-coded for the 57A CAPEX pilot; future migrations that reuse this macro should either update the class or wrap the call with their own div). The 57A test asserts both classes are present on the rendered HTML.
