A first 10-minute walkthrough
  1. Open Model. Start with a Solar or Wind reference and create an editable working copy.
  2. Change one or two assumptions. Capacity, pricing or a financing input is enough for a first run.
  3. Run the model. The run creates the authoritative Last Run output set.
  4. Read Radar separately. Market and company context does not silently rewrite project assumptions.
  5. Inspect evidence when it matters. Use lineage, snapshot and freshness information before treating a number as current or comparable.

FINCO Model

From working assumptions to a Last Run.

Model is a financial calculation workspace. The most important distinction is Working versus Last Run: an editable value can be saved and still differ from the assumptions used in the last committed calculation.

1
Project Library

Open a reference model or an existing working project. Solar, Wind and Data Center are the main production modelling verticals.

2
Inputs

Edit project assumptions in Revenue, CAPEX, OPEX, Financing, Tax and related sections.

3
Run

Commit one deterministic calculation. The resulting snapshot becomes the Last Run authority for outputs tied to that run.

4
Results

Review decision KPIs, cash flow, debt, coverage, statements, distributions and returns.

5
Scenarios & sensitivities

Compare changed assumptions without treating an un-run working edit as a committed result.

6
Export

Use run-bound export paths when an artifact needs an explicit calculation authority and lineage.

What the model calculates

  • Operating and revenue assumptions
  • CAPEX, OPEX and escalation
  • Senior debt and sponsor funding
  • Tax, depreciation and reserves
  • Cash waterfalls and financial statements
  • Distributions, returns and coverage metrics

Reference models

Canonical Solar, Wind and Data Center reference models are synthetic product references. They are useful for onboarding, scaling previews and stateless API runs; they are not market benchmarks or a representation of a specific real project.

Reading the outputs

Use defined financial quantities, not generic health scores.

OutputHow to read itAvoid
Project / Equity / Sponsor IRRReturn calculated from the corresponding canonical cash-flow series.Treating different IRR definitions as interchangeable.

FINCO Radar

Stocks, Crypto and Economy keep their own data semantics.

Stocks

Company fundamentals, financial history, corporate actions, tokenized-market context and amount-specific execution simulation.

  • Featured Equities for discovery
  • Company Terminal for canonical asset identity
  • Underlying company context kept separate from token market state
  • Execution Simulation is analytics only; no order is submitted

Crypto

Global market state plus focused market-structure views.

  • Crypto Overview
  • Stablecoin liquidity and supply
  • Perpetual funding, leverage and liquidity context
  • Tokenized RWA market universe and leaders

Economy

Rates, inflation, inflation expectations, labour and funding conditions with explicit period/freshness handling.

  • Unavailable evidence is not silently substituted
  • Series are interpreted with their own observation periods
  • Macro context does not automatically rewrite Model assumptions

Evidence & verification

A digest identifies evidence; it does not make an external fact true.

FINCO uses source, period, snapshot and lineage information to keep calculations and observations auditable. Supported verification checks deterministic identity and configured internal relationships. It does not replace an external publisher, filing or legal source with a second FINCO truth.

NUMBER→LINEAGE→EVIDENCE→STATUS

Verification can

  • Check deterministic identity of supported evidence.
  • Validate configured relationships and invariants.
  • Preserve run, snapshot, period and source context.

Verification cannot

  • Prove that an external publisher or filing is factually or legally correct.
  • Turn stale or unavailable evidence into a plausible current value.
  • Claim on-chain anchoring while verification remains off-chain.

The validation corpus remains an advanced, non-discoverable product surface rather than a primary navigation item.

Shared concepts

Terms used across FINCO.

Working
The current editable workspace state. It may differ from the assumptions used for the Last Run.
Last Run
The last committed deterministic calculation authority and its bound input/scenario state.
Runtime snapshot
An immutable record of an acquired model or market runtime state used for evidence and replay.
Canonical authority
The designated source of truth for a particular calculation, identity or state within a defined scope.
Lineage
The sources, versions, periods, snapshots and transformations that produced an output.
Freshness
Whether observed evidence remains inside its configured time or period validity window.
Unavailable / Partial / Stale
Explicit states preferred over guessed or silently substituted values when required evidence is missing or old.

Status & limitations

Code capability and deployed availability are not the same thing.

Implemented

Capability exists in the reviewed repository. This does not imply every environment has deployed or configured it.

Beta

A user-facing capability exists, while its public operating or compatibility contract is still evolving.

Planned

Direction only. Planned work is not described in the present tense and has no implied launch date.

Unavailable

Required evidence or runtime authority is absent. FINCO prefers this to a synthetic fallback.

Model: Solar, Wind and Data Center are the main production modelling verticals. Storage is limited/reference scope. EV Charging is in development and not yet released.

Radar: Current Stocks, Crypto and Economy intelligence is read-only. No custody, wallet signing or order submission is represented as current product capability.

Verification: Current verification is off-chain. A content digest proves deterministic identity of the hashed content, not truth of an external source.

API: Real Beta endpoints exist; SDK/webhooks and a broader supported contract remain future work.

$FINCO: The token remains planned and is not a calculation authority. It does not change model outputs, valuation mathematics, quote economics or evidence truth.

FINCO documentation describes product behavior and interpretation boundaries. Where deployment state differs from repository capability, the deployed environment is authoritative for availability.
